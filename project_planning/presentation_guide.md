# Code Clinic Project - Presentation Guide

## STEP 3: Plan Presentation (Day 3 - Wednesday)
**Duration:** 10 minutes presentation + questions  
**Audience:** WTC staff, mentors, external experts  
**Format:** Work from GitLab Issues board and Miro planning docs  

### Presentation Structure (10 minutes)

#### 1. Team Introduction (1 minute)
**Speaker:** Team Lead/Scrum Master
- Team name and members
- Individual exercise status update
- Team coordination approach

**Script Template:**
> "Good morning, we are [Team Name]. Our team consists of [names and roles]. 
> [X] members are caught up on individual exercises, [Y] members are working 
> on catch-up with our support plan. We've established daily stand-ups at 
> [time] and are using [communication method] for coordination."

#### 2. Project Understanding (2 minutes)
**Speaker:** Product Owner
- Demonstrate understanding of Code Clinic requirements
- Key features and user personas
- Success criteria

**Key Points to Cover:**
- Student and volunteer registration
- Time slot management
- Booking system with Google Calendar integration
- CLI interface
- Data persistence

**Demo:** Show system visualization from your HTML files

#### 3. Technical Approach (3 minutes)
**Speaker:** Technical Lead
- Architecture overview
- Technology stack decisions
- Google Calendar API integration strategy
- Risk mitigation plans

**Show from GitLab:**
- Repository structure
- Technical tasks identified
- API research progress

#### 4. Project Planning (3 minutes)
**Speaker:** Scrum Master
- Show Miro board structure
- Iteration breakdown
- Story point estimates
- Team velocity assumptions

**Navigate through Miro board:**
- Product backlog with epics
- Iteration 1 commitment
- Risk register
- Definition of done

#### 5. Iteration 1 Commitment (1 minute)
**Speaker:** Team Lead
- Specific stories committed for Iteration 1
- Confidence level in delivery
- Support plan for team members

**Example Commitment:**
> "For Iteration 1, we're committing to [X] story points including:
> Student Registration, Volunteer Registration, and Project Setup.
> We're confident in this commitment based on our team capacity analysis."

### Preparation Checklist

#### Before Presentation
- [ ] Miro board is complete and organized
- [ ] GitLab issues are created and labeled
- [ ] Team roles are clearly defined
- [ ] Presentation flow is practiced
- [ ] Technical demos are tested
- [ ] Questions are anticipated

#### Materials to Have Ready
- [ ] Laptop with Miro board open
- [ ] GitLab project open in another tab
- [ ] System visualization HTML files
- [ ] Backup screenshots in case of technical issues
- [ ] Team contact information

#### Technical Setup
- [ ] Internet connection tested
- [ ] Screen sharing capability verified
- [ ] Miro board permissions set to view-only for audience
- [ ] GitLab project visibility confirmed

### Common Questions & Answers

#### Q: "How will you handle team members completing individual exercises?"
**A:** "We've created a support plan where [specific approach]. Team members 
working on catch-up will contribute [X] hours per day to the project, and 
we'll use pair programming to ensure knowledge transfer."

#### Q: "What's your biggest technical risk?"
**A:** "Google Calendar API integration complexity. We're mitigating this by 
starting research early, creating a simple prototype first, and having 
[team member] focus specifically on this component."

#### Q: "How confident are you in your Iteration 1 commitment?"
**A:** "We're [confidence level] confident. We've estimated conservatively 
based on [reasoning], and our commitment includes buffer time for learning 
and integration challenges."

#### Q: "How will you ensure code quality?"
**A:** "We've established a Definition of Done that includes code review, 
testing, and documentation. We're using GitLab's merge request process 
with required approvals."

### Demo Flow for Each Section

#### Miro Board Demo (2-3 minutes)
1. **Team Information Section**
   - Point out team details and coordination plan
   
2. **Product Backlog**
   - Show epic organization
   - Highlight story point estimates
   
3. **Iteration 1 Board**
   - Walk through committed stories
   - Show task breakdown
   
4. **Risk Register**
   - Highlight key risks and mitigation strategies

#### GitLab Demo (1-2 minutes)
1. **Issues Board**
   - Show organized backlog
   - Demonstrate labeling system
   
2. **Repository Structure**
   - Show initial project setup
   - Highlight CI/CD configuration
   
3. **Milestones**
   - Show iteration planning

### Post-Presentation Actions
- [ ] Note all feedback received
- [ ] Update planning documents based on feedback
- [ ] Adjust Iteration 1 commitment if necessary
- [ ] Schedule follow-up with mentor if needed
- [ ] Update team on any changes required

### Backup Plans
- **Technical Issues:** Have screenshots ready
- **Time Overrun:** Prioritize commitment and technical approach
- **Missing Team Member:** Ensure all remaining members can cover any section
- **Miro/GitLab Access Issues:** Have local copies of key information

### Success Metrics for Presentation
- [ ] Demonstrated clear understanding of requirements
- [ ] Showed realistic and well-thought-out planning
- [ ] Exhibited strong team coordination
- [ ] Received constructive feedback
- [ ] Built confidence with stakeholders
- [ ] Identified any gaps in planning
